# Monitoring and Project Closure

## Checkpoint plan
| Checkpoint | Planned review | Record |
|---|---|---|
| Day 2 | Review M1: charter, requirements and WBS | Closed Issues / 12, actual hours, blockers, next actions |
| Day 5 | Review M2: schedule, risks and mockups | Closed Issues / 12, actual hours, milestone forecast |
| Day 8 | Review M3: prototypes and test cases | Closed Issues / 12, unresolved defects, final actions |

Task completion percentage = (Closed Issues ÷ Total Issues) × 100. Example: 4/12 = 33.3%; this is illustrative, not recorded project progress.

## Closure checklist
- Verify supporting files for completed Issues.
- Review all 12 Issues and four milestones.
- Record test outcomes and unresolved work.
- Link the final report and repository.
- Document actual versus planned completion.
- Record lessons learned.

## Lessons to evaluate
Small Issues improve visibility; dependencies expose schedule drivers; checkpoints reveal delays; formal change control prevents uncontrolled scope growth.
